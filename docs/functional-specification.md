# Badminton Manager 기능명세서

- 작성일: 2026-11-18
- 기준 소스: `main`의 `0935124c2097e61aedd207e466e7ca064f72a6aa`
- 목적: 현재 구현된 화면·입력·처리 규칙·예외 조건을 기능별로 정리
- 범위: 한 기기에서 배드민턴 모임을 운영하는 설치형 웹 앱(PWA)

현재 구현을 기술한 문서이며 향후 개발 요구사항과 구분한다. 코드와 기존 설명이 다른 경우 기준 소스의 동작을 우선한다. 이 문서 작성 과정에서 실제 기기·카메라·설치 동작을 새로 검증하지 않았다.

## 1. 사용자와 운영 범위

| 항목 | 명세 |
| --- | --- |
| 사용자 | 앱을 실행한 기기의 모임 운영자 |
| 인증 | 회원가입·로그인 없이 사용 |
| 경기 방식 | 선수 4명, 팀당 2명의 복식 경기 |
| 저장 위치 | 현재 기기·브라우저의 LocalStorage |
| 공유 범위 | 회원 명단을 코드·QR로 전달 가능. 선수 상태·경기 현황의 실시간 동기화는 미구현 |
| 기본 운영 흐름 | 회원 저장 → 참석자 불러오기 또는 게스트 등록 → 코트 추가 → 4명 편성 → 경기 시작 → 경기 종료·다음 경기 승계 → 기록·통계 확인 → 백업 |

## 3. 회원 명단·참석자 관리

회원은 반복해서 사용할 명단이며, 선수는 현재 모임의 참가자다.

| --- | --- | --- | --- |

| MEM-02 | 중복 제외 | 앞뒤 공백을 제거한 이름·성별·급수가 모두 같음 | 같은 회원은 추가하지 않고 제외 수 안내. 동명이인은 이름으로 구분 필요 |
| MEM-03 | 회원 검색·선택 | 이름 부분 검색, 개별 선택·검색 결과 전체 선택·선택 해제 | 한국어 이름순 표시. 검색·탭 전환 중 선택 유지. 이미 참가한 회원은 별도 표시하며 재선택 방지 |

| MEM-05 | 회원 수정 | 이름 하나, 성별·급수 | 연결된 현재 선수의 이름·성별·급수도 반영. 동일 프로필의 기존 회원과 중복되는 수정은 거절 |

| MEM-07 | 현재 선수 명단 저장 | 현재 선수가 존재 | 프로필이 없는 회원을 추가하고 연결 가능한 선수와 연결. 기존 회원 중복 저장 방지 |
| MEM-08 | 게스트 등록 | 등록 창에서 게스트 선택, 한 줄에 한 이름 | 회원 명단에 저장하지 않고 당일 선수로 추가. 게스트 표시와 신규 매칭 보정 적용 |

| ID | 기능 | 입력·조건 | 처리·완료 기준 |
| --- | --- | --- | --- |

| PLR-02 | 휴식·복귀 | 대기 또는 휴식 상태 | 대기 → 휴식은 자동 매칭에서 제외. 휴식 → 대기는 새 대기 시작 시각과 복귀 보정 적용 |
| PLR-03 | 콕 제출 표시 | 선수 선택 | 제출·미제출 전환. 매칭 선발 조건으로 사용하지 않음 |
| PLR-04 | 선수 삭제 | 현재 경기와 다음 예약에 배정되지 않음 | 확인 후 당일 선수 삭제, 지정 파트너 연결 해제. 배정 중이면 먼저 교체·예약 해제 필요 |
| PLR-05 | 대기 시간 표시 | 대기·예약 상태 | 저장된 대기 시작 시각부터 경과한 분 표시. 예약·예약 취소는 대기 시각 유지. 경기 종료·휴식 복귀는 새 시각 사용 |
| PLR-06 | 지정 파트너 | 기존 선수 수정에서 다른 참가자 1명 선택 | 양쪽 선수를 서로 연결. 자기 자신·다른 선수와 이미 연결된 상대 지정은 거절. 변경·해제·선수 삭제 시 양쪽 연결 정리 |

| 상태 | 의미 | 주요 전환 |
| --- | --- | --- |
| 대기 `waiting` | 현재 경기·예약에 속하지 않고 출전 가능 | 등록·경기 종료·예약 해제·휴식 복귀 후 대기 |
| 휴식 `resting` | 자동 매칭에서 제외 | 대기실에서 휴식·복귀 실행 |
| 예약 `reserved` | 다음 경기 또는 대기 코트에 편성 | 경기 시작 시 게임 중, 예약 취소 시 대기 |
| 게임 중 `playing` | 일반 코트의 현재 경기에 참여 | 경기 종료 후 다른 예약이 있으면 예약, 없으면 대기 |

게임 중인 선수도 다음 경기 한 곳에 예약할 수 있다. 이때 대표 상태는 게임 중을 우선한다. 현재 경기 중복 배정과 다음 예약 중복 배정은 각각 제한한다.

## 5. 코트 운영과 경기 진행

| ID | 기능 | 입력·조건 | 처리·완료 기준 |
| --- | --- | --- | --- |
| CRT-01 | 코트 추가 | 일반 또는 대기 코트 선택 | 두 종류의 표시 번호를 각각 부여. 일반 코트는 경기 진행, 대기 코트는 사전 편성에 사용 |
| CRT-02 | 코트 삭제 | 확인 후 실행 | 코트와 해당 배정 제거. 선수는 남아 있는 다른 배정에 맞춰 상태 재계산. 삭제 자체는 경기 종료 기록을 만들지 않음 |
| CRT-03 | 경기 유형 변경 | 자율·남복·여복·혼복 | 선택 유형 저장. 유형 변경만으로 기존 편성을 바꾸거나 새 예약을 만들지 않음 |
| CRT-04 | 자동·수동 편성 | 해당 코트의 다음 예약이 비어 있음 | 4명을 다음 예약에 저장. 빈 일반 코트에서도 편성만으로 경기·타이머·기록을 시작하지 않음 |
| CRT-05 | 경기 시작 | 일반 코트, 다음 예약 존재 | 예약 선수가 다른 코트에서 경기 중이 아니면 현재 경기로 이동하고 타이머 시작 |
| CRT-06 | 경기 종료·승계 | 일반 코트의 현재 경기 존재 | 종료 기록 저장, 종료 시점의 선수별 실제 경기 수 1 증가. 시작 가능한 예약이 있으면 즉시 다음 경기 시작 |
| CRT-07 | 승계 보류 | 예약 선수 중 다른 코트 경기 중인 선수가 존재 | 현재 경기는 종료·기록하고 예약은 보존. 다른 경기 종료 후 해당 코트에서 시작 가능. 다른 코트 종료만으로 보류 경기를 자동 시작하지 않음 |
| CRT-08 | 예약 취소 | 다음 예약 존재 | 다음 편성 제거. 선수 상태 재계산, 이미 대기 중이던 선수의 대기 시작 시각 유지 |
| CRT-09 | 예약 코트 변경 | 다른 코트 선택 | 팀 순서를 유지해 다음 예약 이동. 대상에도 예약이 있으면 맞교환. 현재 경기·타이머 유지 |
| CRT-10 | 대기 코트 배정 | 대기 코트 편성 존재, 일반 코트 선택 | 빈 코트이고 4명 모두 다른 코트에서 경기 중이 아니면 즉시 경기 입장·타이머 시작. 그 외에는 다음 예약으로 이동 |
| CRT-11 | 기존 예약 보존 | 대기 코트 배정 대상에 예약 존재 | 대상의 기존 예약은 출발 대기 코트로 이동. 배정 창에서 경기 입장·대기 입장 및 예약 맞바꾸기 표시 |
| CRT-12 | 팀 변경 | 현재 경기 또는 다음 예약의 상대 팀 선수 선택 | 두 선수 자리만 변경. 혼복 코트는 같은 성별끼리 허용. 경기 시각·타이머 유지 |
| CRT-13 | 선수 교체 | 현재 경기는 대기 선수, 다음 예약은 대기·경기 중 선수 선택 가능 | 이미 다른 다음 예약에 배정된 선수는 제외. 해당 자리만 교체하고 상태 재계산 |
| CRT-14 | 연속 누름 방지 | 경기 시작·종료 실행 | 코트별 1초 실행 잠금으로 중복 처리 방지 |

대기 코트에는 현재 경기·타이머·경기 종료 기록이 없다. 경기 중 교체·팀 변경을 한 경우 종료 기록은 종료 시점의 4명과 팀 순서를 사용하며, 교체 전 출전 시간이나 중간 선수 변경 이력을 별도 기록하지 않는다.

수동 매칭과 선수 교체는 자동 선발과 달리 코트 유형에 따른 성별 인원 제한을 강제하지 않는다. 혼복 팀 변경의 동성 교환 제한과 구분해 운영해야 한다.

## 6. 매칭 규칙

### 6.1 자동 선발

1. 휴식 선수와 이미 다음 예약에 들어간 선수를 제외한다. 대기 선수를 우선하고 부족한 자리만 경기 중 선수로 보충한다. 혼복은 남녀 각각 적용한다.
2. 남복은 남성 4명, 여복은 여성 4명, 혼복은 남녀 각각 2명, 자율은 성별 구분 없이 4명을 선발한다. 인원이 부족하면 안내 후 배정하지 않는다.
3. 같은 선발 집단에서 `매칭용 경기 수 = 실제 경기 수 + 보정값`이 적은 선수를 우선한다. 동률에서는 대기 시작 시각을 비교하고 시각도 같으면 무작위 순서를 사용한다.
4. 선발 경계보다 경기 수가 적은 선수와 경계의 최장 대기자를 보호한다. 나머지 동률 후보는 기본 16분 또는 해당 코트의 유효 경기 시간 + 1분 중 큰 범위에서 비교한다. 경기 시간은 기록 배열 앞의 최대 100건 중 해당 코트의 시작·종료 시각이 유효하고 종료가 시작보다 늦은 첫 기록을 사용한다. 경계 후보 수는 최대 12명이다.
5. 허용 후보 조합 안에서 `유효한 지정 파트너 쌍 수가 많은 조합 → 동일 4인 조합 반복이 적은 조합 → 동반 출전한 선수 쌍의 횟수 합이 적은 조합 → 대기 시작 시각 합이 작은 조합` 순으로 비교한다. 지정 파트너가 경기 수·대기 보호·대기 선수 우선 규칙을 넘어서 선발되지는 않는다.
6. 반복 판단에는 기록 배열 앞의 최대 100경기와 현재 진행·예약 조합을 사용한다. 후보 조합이 하나이고 두 번 이상 반복된 그룹이 존재하면 다음 대기 시각 그룹까지 비교 범위를 확장할 수 있다.

조합 다양성은 가능한 후보 안에서 개선한다. 엄격한 선착순, 최대 대기 시간, 반복 조합 제거 또는 전체 코트의 전역 최적화를 보장하지 않는다.

### 6.2 신규·휴식 복귀 보정

| 상황 | 처리 |
| --- | --- |
| 신규·게스트 등록·회원 불러오기 | 휴식 외 선수들의 평균 매칭용 경기 수를 소수점 버림한 값까지 보정. 직접 입력한 실제 경기 수가 기준 이상이면 보정 0 |
| 휴식 복귀 | 자신·휴식 선수를 제외한 평균 매칭용 경기 수를 버림한 기준까지 올리되 기존 매칭용 경기 수보다 낮추지 않음 |
| 비교할 활동 선수가 없음 | 신규 기준 0, 휴식 복귀는 기존 값 유지 |
| 통계·실제 경기 수 | 보정값을 합산하지 않음 |

### 6.3 팀 편성과 지정 파트너

자동·수동 모두 선발된 4명을 두 팀으로 나누며, 선택 순서대로 팀을 고정하지 않는다.

| 조건 | 편성 우선순위 |
| --- | --- |
| 유형에 맞는 지정 파트너가 4명 안에 존재 | 지정 파트너를 같은 팀으로 만드는 쌍 수 최대화 → 팀 급수 합 차이 최소화 → 과거 파트너 반복 최소화 |
| 지정 파트너 우선 편성이 없고 남녀 2명씩 선발 | 각 팀 남녀 1명 유지. 팀 급수 합 차이 → 과거 파트너 반복 순으로 최소화 |
| 그 외 | 급수 내림차순 1·4 대 2·3, 1·3 대 2·4, 1·2 대 3·4 비교. 최근 파트너 반복 횟수를 비용으로 사용하고 마지막 조합에는 페널티 5 부여 |

급수 점수는 A=5, B=4, C=3, D=2, E=1이다. 과거 파트너 반복은 기록 배열 앞의 최대 100경기의 같은 팀 횟수다. 혼복 코트에서는 이성 지정만 팀 편성에 적용한다. 지정 저장은 현재 경기·예약을 재편성하지 않으며 다음 편성부터 반영한다. 지정 파트너는 당일 선수 데이터로 저장하고 새 모임에는 승계하지 않는다.

## 7. 경기 기록·점수·통계

| ID | 기능 | 처리·완료 기준 |
| --- | --- | --- |
| REC-01 | 종료 기록 | 코트 식별자, 시작·종료 시각, 선수 ID·이름, 두 팀 구성 저장. 새 기록을 배열 맨 앞에 추가하고, 추가 후 200건을 넘으면 배열 마지막 기록 1건 제거. 일반 운영 시 최신순 최대 200건 유지 |
| REC-02 | 점수 입력·수정 | 두 팀 모두 0~99 정수. 공란·소수·음수·동점 거절. 저장 후 양 팀 점수·승패 갱신. 점수 차의 별도 계산·표시는 없음. 21점 종료 같은 공식 경기 규칙은 강제하지 않음 |
| REC-03 | 전체 통계 | 집계 가능한 기록 경기 수·현재 등록 선수 수·총 출전 수·평균 출전 수 표시. 기록이 있으면 현재 등록 선수 전체의 출전 목록과 같은 팀·상대 조합 상위 3개 표시. 출전 상위 3명은 내부 계산만 하며 화면에서는 사용하지 않음 |
| REC-04 | 선수별 통계 | 선택 선수의 기록 경기 수·함께한 선수 수·같은 팀 선수 수·상대한 선수 수와 선수별 전체·같은 팀·상대 횟수 표시 |
| REC-05 | 미출전 관계 표시 | 본인을 제외한 현재 등록 선수를 관계 목록에 포함하고 만나지 않은 선수는 0회로 표시. 실제 함께한 선수 수에는 포함하지 않음 |
| REC-06 | 삭제·이전 형식 기록 | 현재 선수가 없으면 기록된 이름 사용. 팀 정보는 이전 이름 문자열에서 복원 가능. 선수 ID가 없는 기록은 선수별 관계 집계에서 제외 |

점수가 없어도 출전·관계 통계에 포함할 수 있다. 선수 카드의 실제 경기 수는 직접 수정 가능한 값이며, 보관 기록만 집계하는 출전 통계와 다를 수 있다. 평균 출전 수는 총 출전 수를 기록에 참여한 고유 선수 수로 나눈 값이며, 화면의 현재 등록 선수 수를 분모로 사용하지 않는다.

기록의 200건 유지 규칙과 매칭의 기록 배열 앞의 최대 100경기 참조 범위는 별개다. 백업 복구는 기록의 건수나 날짜순을 정규화하지 않고 입력 배열을 그대로 적용한다. 따라서 201건인 정상 형식의 백업도 복구되며 다음 경기 종료 후에도 201건이 유지된다. 날짜순이 아닌 백업은 화면에서도 그 순서로 표시되고, 매칭은 시간상 최신 여부와 관계없이 배열 앞의 최대 100건을 사용한다. 일반 운영에서 앱이 생성한 배열은 새 기록을 앞에 추가하므로 최신순이다.

## 8. 회원 명단 공유·QR 수신

| ID | 기능 | 처리·완료 기준 |
| --- | --- | --- |
| SHR-01 | 공유 코드 | 저장 회원 전체의 이름·성별·급수만 gzip·Base64url 기반 `BM2-` 코드로 생성. 회원 ID·당일 선수·출석·경기 기록 제외 |
| SHR-02 | 코드·링크 불러오기 | 코드의 공백·줄바꿈 무시. 이전 공유 링크도 지원. 추가·중복 수를 미리 보여주고 사용자 실행 후 기존 회원에 병합 |
| SHR-03 | 중복·오류 처리 | 앞뒤 공백 제거 후 이름·성별·급수로 중복 제외. 손상·형식 오류·크기 제한 초과 데이터는 적용하지 않음 |
| SHR-04 | QR 생성 | 가능하면 전체 명단 한 장, 용량 초과 시 여러 장으로 분할. 이전·다음 페이지 제공. 코드 복사는 항상 전체 명단 대상 |
| SHR-05 | 여러 QR 수신 | 각 페이지를 독립적으로 추가. 전체 명단을 받으려면 모든 페이지를 읽어야 하며 재수신 중복은 제외 |
| SHR-06 | 앱 내 QR 스캔 | 카메라 또는 사진에서 인식 후 회원 추가 미리보기. 카메라는 권한과 HTTPS·localhost 환경 필요. 인식·닫기·앱 전환 시 카메라 종료 |
| SHR-07 | 개인정보·제한 | 최대 2,000명 공유, 이름 최대 120자. 코드·QR은 암호화 아님. 영상·사진을 업로드하지 않고 기기 안에서 처리 |

QR에는 운영 앱 주소와 명단이 포함된다. 명단 병합은 현재 경기·기록을 바꾸지 않으며 되돌릴 수 있다. 압축 API가 없는 브라우저는 압축 코드 기능을 제한하고 기존 QR 방식으로 안내한다. 앱과 필요한 자원이 저장되어 있으면 오프라인에서 명단 코드·QR 기능을 사용할 수 있으나, 최초 앱 접근에는 인터넷이 필요하다.

## 9. 저장·백업·복구·초기화

| ID | 기능 | 처리·완료 기준 |
| --- | --- | --- |
| DAT-01 | 자동 저장 | 회원·선수·코트·기록과 최근 변경 전 상태를 LocalStorage에 저장. 재접속 시 상태·대기 시작 시각 복원 |
| DAT-02 | 저장 실패 | 저장 공간·권한 등의 오류 시 방금 변경을 직전 저장 상태로 되돌리고 오류 안내 |
| DAT-03 | 손상된 저장 데이터 | 자동 덮어쓰기를 막고 기존 데이터를 보존한 채 오류 표시. 정상 JSON 백업을 복구하는 경로 제공 |
| DAT-04 | 최근 작업 되돌리기 | 확인 후 최근 저장 작업 한 단계 복원. 다단계 이력·다시 실행 기능은 제공하지 않음 |
| DAT-05 | JSON 백업 | 회원·선수·코트·기록을 버전 정보와 함께 `BM_Backup_날짜.json`으로 다운로드 |
| DAT-06 | JSON 복구 | 형식·ID 중복·상태·배정 관계·파트너 상호 연결·점수 등을 검사한 후 적용. 잘못된 파일은 현재 데이터 유지 |
| DAT-07 | 이전 백업 호환 | 회원 항목 없는 백업은 기존 회원 유지. 대기 시작 시각 없는 데이터는 초기 읽기 시각 부여. 이전 급수 0은 E조로 정규화 |
| DAT-08 | 복구 전 상태 복원 | 파일 복구 직전 상태를 별도로 저장하고 설정에서 복원. 일반 최근 작업 되돌리기와 구분 |
| DAT-09 | 새 모임 시작 | 확인 후 저장 회원·코트 구성·유형 유지. 당일 선수·파트너·경기 기록·코트 배정·타이머 제거 후 참석자 선택 열기 |
| DAT-10 | 전체 초기화 | 확인 후 회원·선수·기록을 비우고 빈 자율 일반 코트 1개로 초기화. 직후 최근 작업 되돌리기로 한 단계 복원 가능 |

기기·브라우저·설치 환경이 다르면 데이터가 자동 공유되지 않는다. 사이트 데이터 삭제·기기 변경 등에 대비한 보관 수단은 JSON 백업이다. 사용자 계정 기반 서버 백업이나 여러 기기 간 충돌 해결 기능은 없다.
